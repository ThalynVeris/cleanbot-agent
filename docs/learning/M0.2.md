## 3. 核心原理

### 3.1 为什么要两路召回

- **Dense（向量）**擅长语义相近、换了说法的问题，如「扫地机不回家」≈「找不到充电座」。
- **BM25（关键词）**擅长精确词、型号、数字、专有名词，如「HEPA」「2500Pa」。
- 两者的错误互补，所以混合检索在冻结集上把 Hit@3 从 62.5% 提到 81.25%。

### 3.2 BM25 的中文切词

`tokenize_for_bm25` 没有用分词器，而是把中文连续片段拆成**单字 + 相邻双字**：「主刷缠绕」→ `主 刷 缠 绕 主刷 刷缠 缠绕`。

- 优点：零依赖，不会因为分词器切错而漏召回。
- 缺点：「刷缠」这类无意义双字会带来噪声；领域词（如「滚刷」「基站」）没有被当作整体。M3.1 会引入 jieba + 领域词典做 A/B 对比。

### 3.3 RRF（Reciprocal Rank Fusion）

两路分数量纲不同（余弦相似度 vs BM25 得分），不能直接相加。RRF **只看名次**：

```text
score(d) = Σ_每一路  1 / (k + rank_d)      k = 60
```

- 同时出现在两路的文档会累加，自然排到前面；
- k 越大，名次之间的差距越平缓，单一路的第一名不会独占优势。

### 3.4 条件 Rerank

Rerank 模型（交叉编码器）效果好但慢、要花钱。`disagreement` 策略的判断是：**两路第一名一致，说明结果可信，跳过 Rerank**；不一致才调用。验证集上调用减少 52%，Hit@3 不变（M0.1 已把它设为默认值）。

```python
def tokenize_for_bm25(text: str) -> list[str]:
    lowered = text.lower()
    latin = re.findall(r"[a-z0-9]+", lowered)                 # 英文单词和数字整体保留，如 hepa、2500pa
    chinese_runs = re.findall(r"[一-鿿]+", lowered)   # 连续的中文片段
    chinese: list[str] = []
    for run in chinese_runs:
        chinese.extend(run)                                    # 单字
        chinese.extend(run[i : i + 2] for i in range(len(run) - 1))  # 相邻双字
    return latin + chinese


def fuse_rrf(dense: list[KnowledgeHit], sparse: list[KnowledgeHit], rank_constant: int = 60) -> list[KnowledgeHit]:
    candidates: dict[str, KnowledgeHit] = {}
    fusion_scores: dict[str, float] = {}
    for result_set in (dense, sparse):
        for rank, hit in enumerate(result_set, start=1):      # 名次从 1 开始
            if hit.chunk_id not in candidates:
                candidates[hit.chunk_id] = hit.model_copy(deep=True)  # 深拷贝，不修改调用方的对象
            candidate = candidates[hit.chunk_id]
            candidate.dense_score = max(candidate.dense_score, hit.dense_score)
            candidate.sparse_score = max(candidate.sparse_score, hit.sparse_score)
            fusion_scores[hit.chunk_id] = fusion_scores.get(hit.chunk_id, 0.0) + 1.0 / (rank_constant + rank)

    if not fusion_scores:
        return []
    max_fusion = max(fusion_scores.values())
    for chunk_id, candidate in candidates.items():
        candidate.fusion_score = fusion_scores[chunk_id]
        candidate.score = candidate.fusion_score / max_fusion if max_fusion else 0.0  # 归一化到 0~1
    return sorted(candidates.values(), key=lambda hit: hit.fusion_score, reverse=True)
```

## 6. 面试问答

- **Q：为什么不直接把向量分数和 BM25 分数加权相加？**
  A：两者量纲和分布不同，BM25 没有上界，加权需要逐数据集调参且不稳定；RRF 只用名次，无需归一化，鲁棒性更好。代价是丢失了分数差距的信息。
- **Q：Rerank 为什么放在最后，而不是直接对全库做？**
  A：交叉编码器要对每个「查询 + 文档」对单独推理，成本和候选数成正比，只能用于召回后的小集合；召回负责「不漏」，Rerank 负责「排准」。
- **Q：你怎么证明混合检索有效？**
  A：用 60 条验证集选策略，20 条冻结集只跑一次做独立验证，报告 Hit@3、MRR@5、平均/P95 延迟，同时如实写出没达到 85% 目标（English version: I separated a dev set for strategy selection from a frozen held-out set that was run exactly once.）
